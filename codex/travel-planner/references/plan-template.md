# Travel Plan Template

按需选用下面的结构，不必全部输出。

## 1. Pre-Plan Questions

首轮回复必须先发这一段精简问卷，再等确认。首轮不要先搜索、不要先写行程。

建议固定成这种结构：

- 我目前已知：
- 我还需要你确认：
- 你回复完这些后，我再开始搜索和规划：

问卷内容：

- 出发地和想去哪里？
- 具体日期或玩几天？
- 几个人去？[独行] / 情侣 / 朋友 / 亲子 / 带老人？
- 预算大概在哪个档位？经济 / [中等] / 舒适 / 度假型？
- 这次最想要什么：[经典路线] / 美食 / 拍照 / 放松 / 亲子 / 性价比 / 少折腾？
- 节奏想轻松一点还是高密度一点？松弛 / [均衡] / 高强度？
- 有什么必须去 / 不想去 / 不能接受的点？
- 输出形式：[纯文字] / 带图 HTML / 一图流 / 文档版？

方括号 `[]` 表示默认档位。根据目的地和用户已知信息调整默认项，但必须让清单里的默认项与后面“按默认档位继续”的说明一致。

输出形式固定使用 `[纯文字] / 带图 HTML / 一图流 / 文档版`。不要把“表格版”“带预算清单”列为输出形式；预算清单、交通建议和预订清单是行程内容，默认应该包含。

只有在用户明确允许时，才可以附一个默认档位：

- 如果你暂时不想细说，我可以先按“第一次去、经典路线、节奏均衡、中等预算、纯文字版”做一版；想看更美观的版本也可以直接说“带图 HTML”或“一图流”

## 4. Option Comparison

在用户还没定方案时，对比 2-4 个选项：

- 季节和天气
- 预算级别
- 往返耗时
- 城市内移动难度
- 亲子 / 老人 / 情侣 / 独行适配度
- 是否需要提前抢票

## 5. Day-by-Day Skeleton

每一天尽量包含：

- 区域 / 城市
- 上午锚点
- 下午锚点
- 晚间安排
- 用餐建议
- 交通方式与预计耗时
- 雨天或体力不足时的替代项
