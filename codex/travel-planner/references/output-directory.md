# Output Directory

需要生成文件时，在写入第一个产物前确定本次行程目录，并让所有后续步骤复用它。这是 JSON、Markdown、HTML、PNG、PDF、文档、图片素材及本次生成的渲染辅助脚本的共同规则，不限于视觉输出。纯聊天、需求澄清或单项查询不创建目录。

## 1. 选择位置

1. **用户明确指定输出路径**：使用给定路径；若指定文件，将其父目录作为本次其他产物的归集位置。明确路径优先于自动目录规则。
2. **已有单次行程**：在该行程或其子目录中修改、切换方案、生成摘要或导出时，复用原行程目录，不因标题或文件格式变化另建目录。
3. **专属旅游总目录**：直接使用 `<旅游总目录>/<单次行程>/`。
4. **通用工作目录**：使用 `<工作目录>/旅行计划/<单次行程>/`。

新行程优先按已知日期、目的地和时长命名，例如 `2026-10-北京3天`；不要编造未确定的日期。修订继续复用原目录。多个候选版本放在同一行程目录，以 `plan-a.json`、`plan-b.html`、`summary.png` 等文件名区分，不为每个版本再套一层 `旅行计划/`。

## 2. 解析与创建

从 skill 目录调用工具，`--workspace` 传用户当前的工作目录，不是 skill 安装目录：

```bash
python3 scripts/output_paths.py --workspace "/path/to/workspace" --trip-name "北京3天"
python3 scripts/output_paths.py --workspace "/path/to/workspace" --trip-name "北京3天" --create
```

默认只返回 JSON，不写文件；需要实际落盘时加 `--create` 创建目录和标记。读取返回的绝对 `path`，本次所有产物都以此为根目录，不让各个生成步骤自行重新猜路径。素材可放在行程内的 `assets/` 等子目录。

`--workspace-type` 支持 `auto`（默认）、`general`、`travel`。用户明确说明某个非标准名称的目录是旅游总目录时，传 `--workspace-type travel`，不增加确认轮次；没有依据时按通用目录处理。已有明确的行程或旅游集合上下文继续优先复用，避免重复嵌套。

修改已有行程时可省略名称：

```bash
python3 scripts/output_paths.py --workspace "/path/to/workspace/旅行计划/北京3天/assets" --create
```

省略 `--trip-name` 只允许复用当前目录或受限祖先中有有效标记的单次行程；没有这种上下文就报缺少名称，不自动猜一个。显式名称必须是有效的单个目录名，非法名称会报错而不会静默改名。若确实要新建另一趟旅行，应传新名称和明确的旅游总目录；在已有行程内传不同名称时，只有找到外层旅游集合才能建立兄弟目录。

返回字段为 `path`、`trip_name`、`workspace`、`workspace_type`、`requested_workspace_type`、`reason`、`collection_path`；`workspace_type` 表示实际识别结果 `general`、`travel` 或 `trip`。`--create` 还返回 `created`，说明本次是否新建目录或写入标记。

## 3. 自动识别边界

只用以下依据识别旅游上下文，不因路径包含 `travel`、存在 `plan.json` 或 HTML 文件就猜它是旅游目录：

- 精确集合名：`旅行计划`、`旅游`、`旅行`、`travel`、`trips`、`travel-plans`、`itineraries`；英文忽略大小写，必须完整匹配目录名。
- 当前或祖先目录中的有效 `.travel-planner.json` 标记。
- 从工作目录开始，最多检查 6 个目录，即当前目录加最多 5 层祖先。检查边界目录本身后，遇到 `.git` 文件或目录、用户主目录或文件系统根目录即停止，不跨项目寻找旅游目录。同层先检查明确的集合名或有效标记，所以旅游集合本身可以是 Git 仓库。

标记由工具创建，不需要手工维护。旅游集合使用：

```json
{"kind": "collection"}
```

单次行程使用：

```json
{"kind": "trip", "trip_name": "北京3天"}
```

损坏、超过 8192 字节或为符号链接的标记会报错，不按“未识别”静默绕过。目标是文件、符号链接、非空且未标记的同名目录，或含不匹配的行程标记时也会报错；空的同名目录可写入标记后复用。不要为了绕过错误而改用更宽泛的目录猜测。

## 4. HTML 与其他导出

`visual_plan.py` 未指定 `--output` 时采用同一套目录规则，输出文件名为 `travel-plan.html`，并支持 `--workspace`、`--workspace-type`、`--trip-name`。

- 未显式传 `--workspace`，且输入 JSON 位于有标记的单次行程内时，复用该目录；同一行程的标题改动不会另建目录。
- 无已有行程上下文且未指定 `--trip-name` 时，视觉脚本从 JSON `title` 或输入文件名生成安全名称：不安全字符替换为短横线，不超过 80 个字符且符合目录长度限制。这不改变目录工具对显式名称的严格验证。
- 自动名称与已有非空行程目录重名时拒绝覆盖，也不自行添加后缀另建目录。修订已有行程时，使用该行程内的 JSON，或显式指定 `--trip-name` 表明复用；新旅行则明确采用不同的日期与行程名称。
- 显式 `--output` 覆盖自动托管；相对路径按进程当前目录解析，`--workspace` 等参数不参与。只创建目标父目录和必要素材目录，不额外创建集合或标记。Python 的 `write_plan` 同样采用明确输出路径。

PNG、PDF、Markdown、其他文档和渲染辅助脚本也写入已选行程目录；不要因从 HTML 切换到其他格式再次解析出新目录。交付时提供实际产物链接，并保留 HTML 与相邻素材目录的相对关系。
